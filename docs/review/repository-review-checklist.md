# リポジトリレビューチェックリスト

対象：既存のコードリポジトリ（本テンプレート由来か否かを問わない）。
目的：実装が指針に適合しているかを、文書ではなくコードと設定で検証する。各項目に grep / 目視の手順を添える。
判定：各項目を「合格 / 指摘 / 対象外（理由）」で記録し、`docs/review/README.md` の findings 表へ転記する。証跡欄にはファイル名と行番号を書く。
根拠：「根拠」列の `E-NN` は [evidence-register.md](./evidence-register.md) を参照。

前提ツール：`rg`（ripgrep）または `grep -rn`。以下のコマンド例は ripgrep 構文。Windows では Git Bash から実行する。
cdk-nag の版数に注意：テンプレートは cdk-nag v2 系（`NagSuppressions`）を使う。v3 では `Validations.of(construct).acknowledge({ id, reason })` に置き換わるため、両方を検査する（根拠 E-38）。

## 監査の記録

- `cdk synth` の出力（`cdk.out/`）を根拠に使う場合は commit SHA と synth 日時を findings に残す。
- grep 結果が 0 件で合格とする項目は、検索対象ディレクトリ名も記録する（検索漏れの再確認のため）。
- 本チェックリストで検出できないもの（例：`tenantId` を正しく取得した後に別変数へ入れ替える実装）は、3-1〜3-5 の該当ファイルを目視で読む。
- 上限値（quota、サイズ）は台帳の確認日時点の値である。監査時に AWS ドキュメントで再確認し、差異があれば台帳を更新する。
