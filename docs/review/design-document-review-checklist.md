# 設計書レビューチェックリスト

対象：特定マイクロサービスの設計書（詳細設計、技術設計、Design Doc）。
目的：実装着手前に、境界・契約・信頼性・性能・運用の判断が具体値で決まっているかを確認し、Blocker を実装前に潰す。
判定：各項目を「合格 / 指摘 / 対象外（理由）」で記録し、`docs/review/README.md` の findings 表へ転記する。
根拠：「根拠」列の `E-NN` は [evidence-register.md](./evidence-register.md) を参照。数値上限は確認日時点の値であり、設計書に転記する際は再確認する。

前提：設計書の冒頭に `service.yaml` と同じ所有メタデータが転記されていること。`ownerTeam` と `onCall` が空欄の設計書はレビューを開始しない（指針 §3、根拠 E-73）。
